# Synthetic Data Directory

This directory contains synthetically generated data, scripts, and visualization tools for the Organization System project.

## Purpose

The purpose of this directory is to isolate generated test data and associated utilities from the core schema definitions. It serves as a playground and verification area for the schemas defined in the parent directory.

## System Overview

1. **Enterprise Software Simulation**: The Organization, Message, Document, and Calendar datasets collectively simulate the data generated by an enterprise office software suite.
2. **Data Relationships**: These synthetic datasets are interconnected. The user and organization information used in the **Message**, **Document**, and **Calendar** systems are all derived from the **Organization System** data.

## Data Visibility & Permissions

### Multi-Organization Data Isolation

The synthetic data contains **multiple independent organizations** (e.g., Jaco, Beem). Data between different organizations is **strictly isolated** and mutually invisible:

- Users from **Organization A** can **only access** data belonging to Organization A
- Data from **Organization B** is **completely invisible** to users from Organization A
- All queries must be scoped to a specific organization context (e.g., via `org_id`)
- Cross-organization data access is **not permitted** under any circumstances

**Example**: A Jaco employee (org_id=1) cannot view Beem employee information, access Beem documents, or see Beem calendar events.

### System-Specific Permissions

1. **Organization Data**: Generally public within the organization. Any employee can view information about all other employees and departments within the same organization.
2. **Message Data**: Strictly permission-controlled. Users can only access messages they have permission for, which includes 1:1 chats they are part of and group chats they are members of.
3. **Document Data**: Strictly permission-controlled. Users can only access documents they have permission for, which includes documents they own and documents shared with them.
4. **Calendar Data**: Generally public within the organization. Employees can typically view the calendar availability of all other employees within the same organization.

## Contents

- **org_system/**: Contains the synthetic data generation and visualization logic for the Organization System (Org, User, Dept).
  - **data/**: Raw synthetic tables exported as plain-text files.
  - **scripts/**: Generate, convert, and validate Organization System datasets.
  - **web/**: Simple browser-based viewer for generated JSON data.
  - Schema Definition: [org_system_schema_simplified.md](../org_system_schema_simplified.md)
- **message/**: Contains the synthetic data generation and validation logic for the IM System (Message, Session Participant).
  - **data/**: Raw synthetic message/session-participant tables exported as plain-text files.
  - **scripts/**: Generate, convert, and validate IM datasets.
  - **web/**: Simple browser-based viewer for generated JSON data.
  - Schema Definition: [message.md](../message.md)
- **doc/**: Contains the synthetic data generation and visualization logic for the Document System (Docs, Access Permissions).
  - **data/**: Raw synthetic document/access tables exported as plain-text files.
  - **scripts/**: Generate, convert, and validate Document System datasets.
  - **web/**: Simple browser-based viewer for generated JSON data.
  - Schema Definition: [doc.md](../doc.md)
- **calendar/**: Contains the synthetic data generation and visualization logic for the Calendar System (Calendar Events).
  - **data/**: Raw synthetic calendar-event tables exported as plain-text files.
  - **scripts/**: Generate and convert Calendar System datasets.
  - **web/**: Simple browser-based viewer for generated JSON data.
  - Schema Definition: [calendar.md](../calendar.md)
